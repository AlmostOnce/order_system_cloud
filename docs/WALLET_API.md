# 账户中心与模拟充值

本系统充值按用户确认的演示规则实现：输入金额及支付密码后直接记入余额，不创建第三方支付单、不调用微信或支付宝。未设置支付密码时先完成设置。余额和流水继续由 user-service 同库管理。

## 接口

经 Gateway 统一加 `/api` 前缀。

| 方法与路径 | 用途 | 权限 |
|---|---|---|
| `GET /users/me/profile` | 本人用户名、身份、邮箱、手机号、头像及注册时间 | 已登录 |
| `GET /users/me/balance` | 本人余额和支付密码设置状态，复用现有接口 | CUSTOMER |
| `PUT /users/pay-password` | 首次设置或修改支付密码，复用现有接口 | CUSTOMER |
| `POST /users/me/recharges` | 模拟充值，校验支付密码后到账 | CUSTOMER |
| `GET /users/me/balance/records` | 本人充值、余额消费及退款流水 | CUSTOMER |

所有本人接口都从已校验的 JWT subject 获取用户 ID，不接受客户端指定目标用户。资料采用字段白名单，不返回登录密码或支付密码哈希。

### 模拟充值

请求头：`Idempotency-Key`，8–64 位字母、数字、下划线或连字符，同一笔请求的重试必须使用原值。

```json
{
  "amount": 50.00,
  "payPassword": "本次输入的支付密码"
}
```

单次金额为 0.01–10000 元，最多两位小数。金额、密码在服务端再次校验。复用现有支付密码校验、Redis 错误计数与锁定策略；首次设置用登录密码确认身份，修改使用原支付密码，现有规则不变。

事务内先锁定本人余额行，再查 `(user_id, MOCK_RECHARGE, Idempotency-Key, RECHARGE)` 流水。已入账的同金额请求直接返回原流水，不重复加余额；同一键不同金额返回 409。新请求验证支付密码后，原子累加余额并写 `balance_records`。任一步失败回滚，余额不能超过数据库 DECIMAL(10,2) 上限。不记录或持久化支付密码。

返回 `recordId`、`changeType=RECHARGE`、`amount`、`balanceAfter`、`bizRef`、`remark=模拟充值`、`createdAt`。`balanceAfter` 是本次入账后的历史余额；当前余额以余额查询接口为准。

### 流水分页

参数：`type` 可省略，或为 `RECHARGE` / `PAY` / `REFUND`；`beforeId` 是上一页返回的 `nextCursor`；`limit` 默认 20，范围 1–50。

```json
{
  "code": "COMMON_000",
  "message": "操作成功",
  "data": {
    "items": [],
    "nextCursor": null,
    "hasMore": false
  }
}
```

按 `record_id DESC` 游标分页，始终限定当前用户；只有已提交的真实流水才会展示。消费入口展示余额支付产生的 PAY 流水，不伪造订单或消费数据。金额以正数保存，显示方向由变动类型决定。

## 用户端

- “我的”改为账户中心：身份资料卡、余额卡、充值按钮、余额明细、充值记录、消费记录、个人资料及支付密码。
- 新增充值、流水、支付密码、个人资料四个页面，沿用橙色风格及公共账户样式。
- 充值与支付密码页面在离开时清空密码。充值仅保存与用户 ID 隔离的待确认金额及请求键，网络中断后可以原键重试；刷新令牌后的重试保留相同请求头。
- 未设置支付密码时进入设置页，保存后转入充值。余额错误显示错误与重试，不当成 0 元。充值成功、返回“我的”时重新查询当前余额。
- 资金入口仅对 CUSTOMER 展示；其他角色仍可查看本人资料。
