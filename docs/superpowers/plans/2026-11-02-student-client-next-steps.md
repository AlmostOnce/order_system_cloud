## 4. 重点验收风险

1. 支付成功与超时取消同时发生：不能出现订单已取消却扣款成功后无人处理，不能重复回补库存。任务1必须验证。
2. 邮箱验证码跨用途、跨账号或重放：注册、换绑、找回登录密码、重置支付密码不能互相授权。任务2至4必须验证。
3. 订单分页期间有新订单或状态变化：不能跨用户读取、重复追加或沿用旧筛选游标。任务5必须验证。
4. 退出/切换账号后晚到的通知或 HTTP 响应：不能覆盖新账号页面，也不能泄露旧订单数据。任务6必须验证。
5. 退款或聊天缺少业务规则：不能自定已完成后的退款时限、会话开放时长、审批权限或消息保留期。任务7至8先确认，再设计。

**状态：** 已实施（2026-11-24）。user_db V13 已在开发库执行并核验；user-service、order-service、support-service、auth-service 源码与学生端页面、隐私政策均已完成静态检查，前端 `node scripts/test-vapor.cjs` 通过。真实邮件、跨服务联调、冷静期与到期任务运行验收待执行；未运行 Maven、构建或重启服务。

**目标：** 在订单、退款、工单和资金结清的前提下提供学生自助注销；注销不是物理删除业务记录，而是“72 小时可撤回的账号终止流程 + 到期匿名化”，既满足用户退出诉求，也保留结算、审计与争议处理所需数据。

### 9.1 已确认规则

| 项目         | 规则                                                                                                             |
|--------------|------------------------------------------------------------------------------------------------------------------|
| 适用角色     | 仅 CUSTOMER 可自助注销；店主、经理、管理员等角色由管理端处理，不进入 uni-app                                      |
| 冷静期       | 提交成功后 72 小时生效；期间可撤回，撤回后恢复普通账号                                                            |
| 会话处理     | 提交成功立即递增 `credential_version`，刷新令牌全部失效；提交请求携带的访问令牌同步写入各资源服务共用的黑名单，本机立即下线。其他设备已签发的访问令牌受现有架构限制，会在剩余有效期内自然过期且无法续期 |
| 冷静期登录   | 不发放正常 access/refresh token，只返回“注销待生效”状态、生效时间和一次性撤回令牌；前端只展示倒计时与撤回操作     |
| 余额上限     | 可放弃余额上限默认 **20.00 元**，配置项 `account-deletion.max-forfeitable-balance`；超过上限阻断注销               |
| 余额确认     | `0 < 余额 ≤ 20` 时，提交前弹窗展示“当前余额 ¥X，注销后不予退还”，用户确认后才允许提交；余额为 0 不弹余额窗        |
| 被拒退款     | `REJECTED` 退款不阻断注销，但确认页提示“注销后将无法再申诉”                                                       |
| 到期复核     | 到期时发现未完成订单、未结案退款或未关闭工单，撤销注销并邮件通知；用户处理后可重新申请                            |
| 注销结果     | 账号不可登录并匿名化；订单、支付退款、余额流水、工单正文保留                                                      |
| 撤回令牌     | 一次性、10 分钟有效；只保存在前端内存，不写入本机存储                                                             |
| 重复申请     | 注销待生效期间重复提交返回原生效时间，不重新计时、不延长冷静期                                                    |
| 频率限制     | 注销验证码 60 秒一次、10 分钟最多 5 次；注销申请与撤回按用户限流，防止邮件轰炸和接口滥用                          |

### 9.2 注销阻断条件

| 来源        | 阻断条件                                                                 | 说明                                                         |
|-------------|--------------------------------------------------------------------------|--------------------------------------------------------------|
| 订单        | `待支付`、`已支付`、`制作中`、`待取货`                                   | 对应 `PENDING_PAYMENT`、`PAID`、`PREPARING`、`WAITING_FOR_PICKUP` |
| 退款        | `PENDING`、`APPEALED`、`APPROVED`、`PROCESSING`                          | 未结案退款；`REJECTED` 不阻断但提示放弃申诉，`SUCCESS`/`CLOSED` 为终态 |
| 工单        | `PENDING`、`PROCESSING`                                                  | 与 `SupportStatus` 一致，`CLOSED` 才视为已关闭                |
| 余额        | 大于 `account-deletion.max-forfeitable-balance`，默认 20.00 元           | 提示先消费到上限以内，或通过帮助与反馈申请人工退款            |
| 账号状态    | 非正常状态、正在接受违规调查或存在未结清赔付                             | 此类账号通常无法正常登录，走人工反馈处理                      |
| 内部查询    | order-service 或 support-service 阻断查询失败                            | 按 fail-closed 拒绝申请，不能因依赖不可用而放行注销           |

订单与退款数量由 order-service 内部接口返回，工单数量由 support-service 内部接口返回；user-service 只负责汇总判定，不跨库直接查询其他服务。

### 9.3 状态机与数据字段

```text
正常 --提交注销--> 待生效（72 小时，已下线）
待生效 --撤回--> 正常
待生效 --到期复核通过--> 已注销（匿名化）
待生效 --到期复核发现阻断--> 正常（撤销注销并通知）
```

`user_db` 新增 `V13__add_account_deletion_fields.sql`，在 `users` 表增加：

- `deletion_requested_at`：注销申请时间
- `deletion_effective_at`：注销生效时间，默认申请时间 + 72 小时
- `deletion_reminded_at`：24 小时提醒邮件发送时间，用于去重
- 为 `deletion_effective_at` 增加索引，供到期任务扫描

不新增注销申请表；同一用户只允许一条待生效记录，`deleted_at` 表示注销完成。冷静期小时数做成配置 `account-deletion.cooling-off-hours:72`，便于开发环境缩短验证。

### 9.4 提交与撤回流程

1. **资格查询**：学生进入注销页时读取阻断项、当前余额、可放弃上限和已有注销状态；有阻断时只展示原因和返回入口。
2. **邮箱验证**：向当前绑定邮箱发送验证码，验证通过后换取一次性注销授权令牌（10 分钟）；验证码只存摘要，错误次数受限，成功或过期即作废。
3. **提交注销**：在用户行锁内重新校验阻断项、余额上限和授权令牌；客户端已确认放弃余额时提交 `forfeitBalance=true`；写入申请时间与生效时间，递增 `credential_version`，将当前访问令牌加入各资源服务共用的黑名单，清理授权令牌，并发送确认邮件（含生效时间与撤回方式）。
4. **冷静期登录**：密码校验通过后发现存在待生效注销，不签发正常令牌，返回 `deletionPending=true`、`deletionEffectiveAt` 和一次性撤回令牌；前端进入待生效页，除撤回外不提供点餐、支付、退款、工单等操作。
5. **撤回注销**：消费撤回令牌并清空注销字段，发送撤回确认邮件；之后按普通账号重新登录。撤回失败或令牌过期时重新登录获取新令牌。
6. **到期提醒**：距生效不足 24 小时且未提醒过时发送提醒邮件；提醒失败只记日志，不阻断后续注销。
7. **到期处理**：定时任务按租约抢占处理权，逐用户事务复核；通过则匿名化，存在阻断则撤销注销并邮件通知原因。

邮件发送全部按尽力而为处理：验证码发送失败必须提示用户重试且不得进入下一步；确认邮件、提醒邮件和完成邮件失败只记录日志，不回滚已生效状态。

### 9.5 到期处理与数据处置

到期任务建议每 5 分钟扫描一次，单次限量处理；先用条件更新抢占租约，避免多实例重复处理，再在事务内重新核验阻断项。复核失败时：

- 清空 `deletion_requested_at`、`deletion_effective_at`、`deletion_reminded_at`
- 保持账号正常可用，邮件通知“注销未完成”的具体原因
- 不自动延期，用户处理后可重新申请

复核通过后的数据处置：

| 数据                                   | 处理方式                                                                 |
|----------------------------------------|--------------------------------------------------------------------------|
| `username`                             | 改为 `已注销用户_{userUuid}`，借助用户唯一标识避免重名                    |
| `email`                                | 置为 `NULL`，释放唯一键；注销完成后同一邮箱可注册全新账号                 |
| `avatar_file_key`                      | 置空，不再展示头像                                                       |
| `password_hash`                        | 写入随机不可用哈希，确保旧密码无法登录                                   |
| `balance`                              | 清零；大于 0 时写一条 `WRITE_OFF` 余额流水，业务类型 `ACCOUNT_DELETION`   |
| `status` / `deleted_at`                | `status=0`，写入 `deleted_at`，并再次递增 `credential_version` 和 `version` |
| `user_no`、`user_uuid`                 | 保留且不复用，避免历史订单与身份混淆                                     |
| 订单、支付、退款、余额流水、工单       | 保留，用于结算、审计和争议处理                                           |
| 评价、聊天消息                         | 保留内容，展示为“已注销用户”，不展示原昵称和头像                         |
| 收藏、通知、购物车草稿                 | 删除或清理                                                               |
| 优惠券                                 | 标记失效或按过期处理，注销页需提示未使用优惠券将失效                     |
| 本机数据                               | 清除令牌、记住的账号、搜索历史、页面草稿、通知会话和用户级缓存           |

已完成订单的退款期为完成后 72 小时，与注销冷静期一致。提交注销后用户无法再申请退款，确认页必须提示“近期订单如需售后请先退款或撤回注销”。注销完成后邮箱可立即重新注册，新账号与旧账号的历史订单、余额、优惠券不迁移。

### 9.6 接口与跨服务改动

user-service：

- `GET /users/me/deletion/eligibility`：返回阻断项、余额、可放弃上限、待生效时间
- `POST /users/me/deletion/verification-code`：发送注销邮箱验证码
- `POST /users/me/deletion/authorization`：验证验证码并签发一次性注销授权令牌
- `POST /users/me/deletion`：提交注销，携带授权令牌与放弃余额确认
- `POST /users/me/deletion/cancel`：使用撤回令牌撤回注销
- 内部接口 `POST /internal/users/{userId}/deletion/cancel-token`：供 auth-service 在待生效登录时签发一次性撤回令牌

order-service / support-service：

- `GET /internal/users/{userId}/account-deletion/blockers`：分别返回未完成订单与退款数量、未关闭工单数量；沿用现有内部令牌与 Feign 调用方式

auth-service：

- `UserBasicVO` 增加注销待生效信息，供登录判断
- `LoginVO` 增加 `deletionPending`、`deletionEffectiveAt`、`deletionCancelToken`、`deletionCancelExpiresIn`
- 待生效账号只返回撤回所需信息，不返回正常 access/refresh token

隐私政策：

- 更新 `common/legal.uts`，把“未开放自助注销”改为已开放的注销方式、72 小时冷静期、余额处理、数据保留与匿名化范围
- 同步递增协议版本号和更新日期

管理端不新增注销审批入口；如需查看待注销账号或人工处理争议，另立管理端需求。

### 9.7 学生端页面与交互

- 入口放在「我的-账号与安全」，使用危险操作样式，与修改密码、支付密码分开
- 新增注销说明页：展示阻断项、当前余额、可放弃上限、72 小时规则、数据保留范围和风险提示
- 余额弹窗：`0 < 余额 ≤ 20` 时展示具体金额与“注销后不予退还”，必须勾选确认；超过 20 元只展示阻断提示，不提供提交按钮
- 被拒退款提示：存在 `REJECTED` 退款时展示“注销后无法再申诉”，不阻断提交
- 邮箱验证码：发送按钮倒计时、错误次数提示、离页清理验证码
- 提交成功后清理本机登录态和用户级缓存，展示“注销申请已提交”结果页
- 待生效页：登录特殊态进入，展示剩余时间和撤回按钮；撤回成功后清除内存令牌并回登录页
- 所有注销相关页面不得把验证码、授权令牌、撤回令牌写入日志或本地存储

### 9.8 验证与验收

- 资格与阻断：未完成订单、处理中退款、未关闭工单、余额超过 20 元分别阻断；被拒退款不阻断且展示提示
- 余额边界：`20.00` 允许并弹窗，`20.01` 阻断；`0` 不弹余额窗；确认放弃后余额清零并生成 `WRITE_OFF` 流水
- 邮箱验证：验证码错误次数、过期、跨用户、重放均被拒绝；授权令牌一次性
- 会话：提交后旧 access/refresh token 全部失效；冷静期登录不返回正常令牌；撤回后可正常登录
- 流程：重复提交不延长生效时间；撤回后再次申请正常；到期前 24 小时提醒只发一次
- 任务：多实例并发只处理一次；到期复核发现阻断时撤销并通知；任务异常可重试
- 匿名化：邮箱释放后可重新注册；旧密码不可登录；订单、退款、流水、工单仍可按匿名账号查询
- 依赖失败：order-service 或 support-service 不可用时申请被拒绝而不是放行
- 前端：小屏、长文本、键盘遮挡、弱网、验证码倒计时、余额弹窗和待生效倒计时展示
- 后端仍只做源码静态检查；Java 测试、构建和服务启动须获得当前请求明确授权后执行
