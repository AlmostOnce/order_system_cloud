# 评论服务首期实施计划

按既定架构实现独立 comment-service（9105），MongoDB 内容先写、MySQL comment_db 元数据后提交；只通过已认证用户的订单查询确认已完成及菜品购买事实，不跨库读取订单。

1. 新增模块、JWT 安全配置、订单购买事实 DTO，复用订单详情接口、统一响应、用户身份解析、文件归属校验。仅修改必要依赖声明，不运行 Maven。
2. 实现菜品评价创建及请求幂等：同订单同菜品一次，评分1至5、正文最多1000字、最多6张本人评论图片及5个标签；UUID评论号，对外不返回内部用户ID。
3. MongoDB写入不可见的待确认内容；MySQL本地事务提交元数据、评分汇总和outbox。查询以MySQL为可见性依据；24小时宽限后清理孤儿，已提交内容补标记，依赖异常不误删。
4. 实现本人、菜品分页、详情及评分汇总；游标使用评论UUID，返回明确的下一游标。汇总可短期缓存，Redis故障回源。
5. 实现评分快照MQ事件、同步发布确认与退避重试，商品端按评分版本幂等更新本库投影；定时重发最新评分快照补偿Redis/MQ之外的投影遗漏。
6. 补充MongoDB Compose配置、初始化脚本、MySQL中文注释迁移及API说明，网关路由样例。补充测试源码与静态契约检查，不启动基础设施、不执行迁移、不重启服务。

首期只实现后端闭环，不包含商家回复、点赞、评价修改删除、审核后台及用户端页面。上述功能的权限和评分逆向变化留待后续设计。
