# 库存变更 MQ 实施计划

## 目标

在不改变 Seata AT 同步扣减/回补和数据库库存准据的前提下，将已提交库存变更以 RocketMQ 异步传播，首先用于失效 Redis 库存快照。

## 方案

- 继续同步扣减库存；不让订单在异步库存确认前成功。
- 在 `stock_db` 同一事务写入 `stock_flow` 和库存事件 outbox。
- Seata AT 分支的 outbox 记录关联 XID。发布查询排除仍存在于 `undo_log` 的 XID：全局回滚时 outbox 会随分支一起撤销；全局提交清理 undo log 后才允许发送。
- 使用现有 Spring Cloud Stream RocketMQ binder。事件至少一次投递；消费端以事件键幂等删除 Redis 快照，不覆盖库存数量。
- 保留现有定时库存对账；MQ 不可用时 outbox 退避重试。

## 范围与文件

1. `stock-service` POM、配置、事件模型、outbox Mapper/发布器/消费者和 Redis 快照失效方法。
2. `stock-service` 扣减、回补成功后在对应流水旁写 outbox。
3. `docs/database/migrations/stock_db/V2__stock_event_outbox.sql` 创建事件表及消费幂等表。
4. `tools/test-stock-mq.py` 做不触碰 Maven 的源码/配置契约校验。
5. 更新 `docs/STOCK_INTEGRATION.md` 与库存 MQ 操作、验证说明。

## 验收

- 新增事件只在成功扣减/回补流水后写入，幂等重试不生成额外事件。
- 全局事务仍未决时不发布；全局回滚会撤销 outbox；事务结束后发布器能够重试。
- 重复/乱序事件只执行幂等快照删除，消费者失败时向 Broker 抛错触发重试。
- SQL、XML、YAML、源码契约静态检查通过；不运行 Maven、构建、Java 测试或重启服务。

## 限制

静态检查不能替代 Java 类型检查、Seata 回滚实测或 RocketMQ 端到端验收；这些需在用户允许构建/测试与服务操作后完成。
