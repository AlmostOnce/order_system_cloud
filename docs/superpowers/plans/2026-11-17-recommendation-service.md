# 首页推荐服务实施计划

## 目标与约束

按 [推荐服务设计](../../RECOMMENDATION_SERVICE.md) 建立 Java
实现的菜品级个性化推荐，并接入学生首页。首期使用已支付购买、成功退款后的净购买、当前收藏、主动搜索和热门销量；规格选择作为辅助偏好，只有用户实际选择且能映射到明确口味维度的选项参与跨菜品相似度。库存、价格和当前可售性仍由商品域确认，推荐不自动预选规格或下单。

所有请求身份从已验证的 CUSTOMER 会话解析；内部服务调用验证项目现有内部凭据。行为只属于本人。新增及修改的 Java
代码补充中文业务注释。开发库迁移只有在目标与现有结构核实后执行。

## 实施顺序

1. 为核价结果增加服务端生成的结构化规格选项快照，并在订单明细保留 JSON 快照；历史记录按空选择兼容。验证规格选择顺序、价格和原有购物车/订单字段不变。
2. 在支付确认及成功退款事务内写推荐专用订单快照 Outbox，保存订单版本、用户、窗口、支付时间及逐 itemId 的购买/退款份数和规格快照。复用现有
   Outbox 发布模式，不改销量统计事件契约。消费者按版本幂等处理，先扣逐行退款再按订单和菜品聚合封顶。
3. 创建推荐服务最小模块和独立迁移；实现商品级画像及混合排序：文本/目录内容相似、净购买收藏、短期搜索、窗口收藏、热门和随机稳定探索。口味只读取实际所选快照并经过显式规范化；未知规格文字不参与，候选商品“提供该选项”本身不构成用户偏好。
4. 接入经过 CUSTOMER 身份验证的首页接口、受保护内部数据契约、网关路由和配置样例；当前商品批量校验失败时不展示已知失效项，推荐故障不改变首页其它数据。
5. 学生首页复用既有图片、HTTP、账户隔离和菜单定位行为；有规格商品显示基础起价提示，由菜单规格面板重新选择，不自动加购。
6. 更新文档、迁移记录和静态审阅结果。遵守仓库规定：本次不调用 Maven、Wrapper、构建、测试、清理、启动或重启命令；若无法确认开发数据库目标或备份，不执行迁移并记录阻塞项。

## 验收重点

- 同菜不同规格的订单明细保留独立 itemId；每行先计算 `quantity - refundedQuantity`，校验
  `0 <= refundedQuantity <= quantity`，再按 `(orderId, productId)` 合并并执行单订单商品份数上限。
- 退款快照先到时，较旧支付版本不能复活偏好；重复事件不会重复加权；Outbox 写入失败回滚源事务。
- 只有显式选中的、可辨识的口味选项参与规格偏好；没有选择、base 历史或未知选项不推断口味。
- 公开接口仅返回本人推荐；餐厅筛选、规格起价、有效商品及账号切换正确；点击复用既有菜单定位。
- 静态核对接口复用、权限边界、迁移重复执行安全和现有未提交改动；不声称未运行的检查通过。
