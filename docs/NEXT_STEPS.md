# 下一步计划

## 前后端联调边界

用户于 2026-10-30 明确：uni-app 仅作为普通学生端，商家与其他管理角色使用专门的 Vue 管理端。后续联调遵守该划分，不继续扩展 uni-app 的管理能力。

- [ ] 确认现有 Vue 管理端仓库及其接口封装、登录与角色机制。
- [ ] 学生端联调：本人订单、取餐码展示、支付及取消、订单通知、评价；只使用 CUSTOMER 身份。
- [ ] Vue 管理端联调：订单制作与待取货推进、取餐码核销、窗口及菜品图片管理；使用授权商家身份和真实窗口范围。
- [ ] 验证取餐码只由订单所属顾客获取，商家只能提交顾客提供的码；跨窗口、错误码、重复核销及通知链路分别验收。
- [ ] 后端构建、测试、启动仍遵守用户的 Maven 授权限制，不自动执行。

## 调试功能收口

当前 uni-app 管理功能仅临时用于调试。管理端完成后统一清除，不在本次约定时立即删除。

- [ ] 删除 uni-app 的 `pages/manage/images`、`pages/manage/pickup` 页面及相关路由、入口、仅供管理端使用的 API 封装。
- [ ] 清理 uni-app 中非学生角色的调试分支和相关设计文档。
- [ ] uni-app 登录成功前、缓存会话恢复和页面守卫均严格限定 CUSTOMER，拒绝并清理非学生会话。
- [ ] Vue 管理端严格校验允许登录的管理角色，按权限显示页面；服务端角色和数据范围验证继续保留。
- [ ] 验证学生账号不能进入管理功能，管理账号不能进入正式学生端。
