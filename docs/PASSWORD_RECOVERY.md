# 邮件找回登录密码

日期：2026-11-02。当前已完成前后端源码、用户库凭据版本迁移及隔离检查；未运行 Maven、Java 单测或真实邮件端到端联调，不代表运行中的服务已加载新代码。

## 学生端流程

登录页点击“忘记密码？”进入独立页面：

1. 输入账号当前绑定邮箱及图片验证码，申请六位邮件验证码。
2. 输入邮件验证码验证身份，成功后进入设置新密码步骤。
3. 两次输入新登录密码，提交后返回登录；不自动登录。

图片验证通过发送邮件后不再刷新或要求重复填写图片。重新发送邮件需重新获取图片验证码。密码、邮件验证码、重置凭据只保留在当前页面内存，离页清理，不写本地存储。未绑定邮箱的旧账号暂不提供自助找回方式。

此功能只处理忘记登录密码，不包含已登录修改密码、重置支付密码、注册邮箱验证、商家功能。

## 对外接口

均经 Gateway `/api`，允许匿名调用，不需要已有 Token；仅开放以下精确路径。

| 方法 | 路径 | 请求与响应 |
|---|---|---|
| POST | `/api/auth/password-reset/code` | `{email,captchaId,captchaCode}`；受理成功统一返回空 data，不告知邮箱是否有账号 |
| POST | `/api/auth/password-reset/verify` | `{email,code}`；成功返回 `{resetToken,expiresIn:300}` |
| POST | `/api/auth/password-reset/confirm` | `{resetToken,newPassword}`；成功返回空 data |

示例字段 `code` 必须为字符串，例如 `"012345"`，不能丢失开头的零。请求 DTO 和授权响应的 toString 隐去敏感字段；禁止记录完整请求体。

新密码规则沿用当前登录注册的6至64字符，并检查 BCrypt 的72字节上限；不去除密码空格，不改变用户输入。保存 BCrypt 哈希，不返回或记录明文。

## 分层与身份验证

- 认证服务校验图片验证码并进行来源限流；通过 `user-api` 中独立 `PasswordRecoveryClient` 调用用户服务内部接口。
- 用户服务内部路径 `/internal/users/password-recovery/code|verify|confirm` 逐次校验 `X-Internal-Token`，不经 Gateway 暴露，也不把内部路径设为匿名业务接口。
- 邮件复用现有 QQ SMTP 与发送组件，找回邮件使用独立主题及用途说明，不发送真实测试邮件来验证单元逻辑。
- 邮箱规范化后精确查找启用且未删除账号；重置只使用服务端授权中的用户编号、邮箱及版本，不接受客户端指定用户ID。

## Redis 凭据与限流

- 找回验证码独立使用 `password-recovery:*` 命名空间，HMAC 包含找回用途、规范化邮箱及验证码；与邮箱换绑验证码、授权票据不互通。
- 邮件验证码有效期10分钟，最多5次错误校验；Lua 原子消费保证成功后不可重放，并保留错误计数时原TTL。
- 每邮箱60秒最多发送1次、10分钟最多3次；发送/验证/确认分别按来源10分钟限制10/30/20次。来源限制沿用既有代理地址解析方式，不作为身份依据。
- 无可用账号也返回相同受理结果，不发邮件、不建账号。SMTP发送失败条件删除该次验证码，仅记录不含邮箱或异常详情的日志，对外不因该邮箱是否有账号而改变受理结果。
- 邮件验证成功生成256位随机重置凭据，有效期5分钟，存储键为HMAC摘要，授权绑定用户、邮箱和当前凭据版本。
- 确认重置前先校验密码格式，读取授权并锁定当前用户行；校验账号、邮箱、凭据版本后，用BCrypt matches检查新密码是否与当前登录密码相同，相同则明确拒绝且不消费授权、不撤销现有会话。通过后比较并原子消费授权，仍保留原5分钟有效期。密码写入失败或响应不确定时，不保留可重复使用的授权；用户可以尝试新密码登录，或重新验证邮箱，不自动重复改密。

## 全部旧会话失效

`user_db.users.credential_version` 为非空 BIGINT，默认0。密码哈希写入与该版本递增在同一条件更新事务中提交，版本、邮箱或账号状态不匹配时拒绝旧重置授权；不修改余额、流水、支付密码、用户号、UUID或角色。

- Access Token 签发时携带 `credential_version`；共用 `JwtUserIdentity` 在解析业务身份时核对用户库当前版本。旧版无此声明的 Token 按0处理，数据库版本不匹配即拒绝。
- Refresh Token 的 Redis Hash 同样保存版本。轮换时先读取用户当前版本，比对失败删除该旧刷新令牌，禁止重新签发会话；旧记录缺字段按0处理，自然TTL继续有效，不扫描删除全部Redis数据。
- 通知握手票据携带用户UUID及凭据版本；连接建立和每次推送前校验版本，旧版本不能继续接收通知；空闲旧连接由既有30秒扫描关闭。
- “旧会话失效”表示之后的认证/续期/推送被拒绝，不代表可以撤销重置前已经在执行的请求，或让所有闲置设备的页面在同一毫秒自动跳转。
