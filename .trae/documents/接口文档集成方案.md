# 接口文档（OpenAPI / Swagger）集成方案

## Context

**为什么做**：项目目前的接口清单只能靠人肉梳理（Method / URL / 参数 / 请求体全靠翻代码或口头整理），已经影响到实际使用——每次要测接口都得手工列一遍，也容易和代码脱节。本次把接口文档固化进项目，目标是：

- 一个入口能看全 6 个服务的接口签名、参数、请求体 schema、响应结构、鉴权要求；
- 支持 "Try it out" 直接打真实接口（便于联调，不用再切 Postman）；
- 可导出 OpenAPI JSON，直接导入 Postman 生成集合；
- 文档与代码同源：改了 Controller 就自动更新，不会再过期。

**现状（已勘察确认）**：

- 根 [pom.xml](file:///e:/order_system_cloud/pom.xml)：Java 21、Spring Boot **3.5.6**、Spring Cloud 2025.0.0、Spring Cloud Alibaba 2025.0.0.0；`dependencyManagement` 只导入了三个 BOM，**无任何 springdoc / springfox / swagger 依赖**。
- 5 个业务服务（order / user / auth / product / payment）均为 **Spring MVC**（`spring-boot-starter-web`）+ Spring Security JWT 资源服务器；gateway 为 **WebFlux**（`spring-cloud-starter-gateway`）。
- 所有 Controller **没有任何 OpenAPI 注解**（`@Operation` / `@Tag` / `@Schema` 均未使用）。
- 网关鉴权是白名单制：`GatewaySecurityConfig` 里逐条 `pathMatchers(...).permitAll()`，最后 `anyExchange().authenticated()`——**新增文档路径必须显式加进白名单**，否则一律 401。
- 各服务鉴权同样是白名单制（如 `PaymentSecurityConfig` 的 `authorizeHttpRequests` 里逐条 `requestMatchers(...).permitAll()`）。
- 文档体系：`docs/PROJECT_PROGRESS.md`（进度与"当前下一步"）、`docs/ARCHITECTURE.md`（含端口表）、`docs/JAVA_CODING_STANDARDS.md`（要求中文 Javadoc、新增类需 `@author/@date`）。
- 注意 `docs/DOCKER_DEV_ENV.md` 里记录的端口（8080/8081/…）**已过期**，实际端口以各 `application.yml` 为准（9090/9091/9092/9093/9094/9101）。

## 技术选型

**springdoc-openapi 2.9.1**（面向 Spring Boot 3.x 的最新版本线；springdoc.org 官方文档当前即对应 v2.9.1），不使用 springfox（对 Boot 3 已停止维护）。

- 5 个业务服务 → `springdoc-openapi-starter-webmvc-ui`
- 网关 → `springdoc-openapi-starter-webflux-ui`（提供聚合入口）
- 版本统一由 BOM 管理（springdoc 自 2.8.7 起提供 `springdoc-openapi-bom`）

**关键取舍**：共享的 `OpenAPI` 定义（标题、版本、JWT Bearer 安全方案、网关 server 前缀）**只写一份**，放在 `common-web`，靠各服务已有的组件扫描生效，避免 5 份重复配置。

## 实施步骤

### 1. 根 pom.xml —— 引入版本管理

- `properties` 新增 `springdoc.version=2.9.1`
- `dependencyManagement` 新增：
  `org.springdoc:springdoc-openapi-bom:${springdoc.version}`（`type=pom`、`scope=import`）
- 落地后先跑一次 `mvn -B dependency:resolve`（`dangerouslyDisableSandbox`）确认能拉到 2.9.1，再继续。

### 2. 各模块加依赖

| 模块 | 依赖 | 说明 |
|---|---|---|
| order / user / auth / product / payment-service | `springdoc-openapi-starter-webmvc-ui` | 无版本，由 BOM 管 |
| gateway-service | `springdoc-openapi-starter-webflux-ui` | 聚合入口 |
| common-web | `springdoc-openapi-starter-webmvc-ui`，`scope=provided` | 仅供编译共享配置类，**不传递**给下游，避免污染所有依赖 common-web 的模块 |

### 3. common-web —— 共享文档配置（新增 1 个类）

新增 `com.hbue.ordering.common.web.docs.OpenApiDocumentationConfig`：

- `@Configuration` + `@ConditionalOnClass(OpenAPI.class)`（未引入 springdoc 的模块自动跳过）+ `@ConditionalOnProperty("springdoc.api-docs.enabled", havingValue="true", matchIfMissing=true)`
- 提供一个 `OpenAPI` bean：
  - `info`：标题/描述/版本取自配置 `springdoc.service-title` / `springdoc.service-description`、`project.version`，缺省回落到 `spring.application.name`
  - `components` 注册名为 `bearerAuth` 的 `SecurityScheme`（`HTTP` / `bearer` / `JWT`），并加一条全局 `SecurityRequirement`，让 UI 右上角出现 "Authorize" 按钮
  - `servers`：显式指定，规避网关重写路径后 server 地址生成错误的问题（见步骤 5）
- 代码注释遵循 [JAVA_CODING_STANDARDS.md](file:///e:/order_system_cloud/docs/JAVA_CODING_STANDARDS.md)：中文 Javadoc + `@author order-system` + `@date`。

**核对项**：5 个服务的启动类是否都是 `scanBasePackages = "com.hbue.ordering"`（user-service 已确认是）。若某个服务只扫自身包，则需在该服务的 `@SpringBootApplication` 上补 `scanBasePackages`，或在服务内自行声明 OpenAPI bean。

### 4. 各服务 SecurityConfig —— 放行文档路径

在 5 个安全配置类的 `authorizeHttpRequests` 白名单里追加一行（按各文件现有风格插入）：

```java
.requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html").permitAll()
```

涉及文件：

- [OrderSecurityConfig.java](file:///e:/order_system_cloud/order-service/src/main/java/com/hbue/ordering/order/config/OrderSecurityConfig.java)
- [UserResourceServerConfig.java](file:///e:/order_system_cloud/user-service/src/main/java/com/hbue/ordering/user/config/UserResourceServerConfig.java)
- [SecurityConfig.java](file:///e:/order_system_cloud/auth-service/src/main/java/com/hbue/ordering/auth/config/SecurityConfig.java)
- [ProductSecurityConfig.java](file:///e:/order_system_cloud/product-service/src/main/java/com/hbue/ordering/product/config/ProductSecurityConfig.java)
- [PaymentSecurityConfig.java](file:///e:/order_system_cloud/payment-service/src/main/java/com/hbue/ordering/payment/config/PaymentSecurityConfig.java)

`/internal/**`、`/mock/**` 的放行规则**保持不动**。

### 5. 网关聚合 —— 一个入口看全部

**(a) 文档路由**：在 Nacos 配置 `gateway-service.yaml`（仓库镜像文件 [docs/nacos/gateway-service.yaml](file:///e:/order_system_cloud/docs/nacos/gateway-service.yaml) 同步改）中为每个服务加一条**文档专用路由**，且必须排在对应服务的 `/api/xxx/**` 路由**之前**（Spring Cloud Gateway 是首个匹配生效）：

```yaml
- id: user-service-docs
  uri: lb://user-service
  predicates:
    - Path=/api/users/v3/api-docs
  filters:
    - RewritePath=/api/users/v3/api-docs, /v3/api-docs
```

5 条分别对应 auth / users / orders / products / payments。这里不能用 `StripPrefix=1`（会把路径变成 `/users/v3/api-docs`，落到不存在的地址），必须用 `RewritePath`。

**(b) 聚合 UI 配置**：gateway `application.yml` 增加：

```yaml
springdoc:
  swagger-ui:
    urls:
      - name: auth-service
        url: /api/auth/v3/api-docs
      # …user / order / product / payment 同构
```

**(c) 网关白名单**：`GatewaySecurityConfig` 的 permitAll 列表追加：

```java
.pathMatchers("/swagger-ui/**", "/swagger-ui.html", "/v3/api-docs/**").permitAll()
.pathMatchers("/api/*/v3/api-docs").permitAll()
```

**(d) server 前缀修正**：经 RewritePath 后，各服务生成的 `servers` 地址会是错的（"Try it out" 会打偏）。因此在步骤 3 的 `OpenAPI` bean 里显式设置 `Server`，各服务 yml 给出自己的网关前缀：

```yaml
springdoc:
  gateway-base-url: ${SWAGGER_GATEWAY_BASE_URL:http://localhost:9090}
  gateway-path: /api/users        # 各服务不同：/api/orders、/api/products…
```

### 6. 开关（便于生产关闭）

各服务（含网关）`application.yml` 追加：

```yaml
springdoc:
  api-docs:
    enabled: ${SWAGGER_ENABLED:true}
  swagger-ui:
    enabled: ${SWAGGER_ENABLED:true}
```

学习项目默认开启；需要关闭时设 `SWAGGER_ENABLED=false` 即可（不必改代码）。

### 7. 文档标注（内部接口不混入对外契约）

- 给 5 类 Controller 加 `@Tag`：对外接口按服务/领域命名，内部接口（`/internal/**`、`/mock/**`）统一标 `内部接口（服务间调用）`。
- 只在**必要处**补 `@Operation(summary)`——优先靠已有的中文 Javadoc 自动生成描述，不做无意义的注解铺量。
- 可选：需要把内部接口从文档里彻底剔除时，用 `springdoc.paths-to-exclude=/internal/**,/mock/**`（默认不加，保留可查性）。

### 8. 文档沉淀

- [PROJECT_PROGRESS.md](file:///e:/order_system_cloud/docs/PROJECT_PROGRESS.md)：新增「2026-10-14 本次完成」条目，记录文档入口地址、开关方式、导出 Postman 的用法。
- 新增 `docs/API_DOCS.md`（简短一页）：入口地址、各服务直连地址、如何导出 Postman、如何关闭、`/internal/**` 为何不在网关暴露。

## 验证方式

1. **编译**：`mvn -B -pl common-web,gateway-service,order-service,user-service,auth-service,product-service,payment-service -am -DskipTests package`（需 `dangerouslyDisableSandbox`，本地仓库在 `D:\repository`）。
2. **回归单测**：`mvn -B -pl user-service,payment-service,order-service,product-service,auth-service -am test`，确认新增依赖未破坏既有测试。
3. **启动**（IDEA，profile=`dev`，gateway 需环境变量 `NACOS_PASSWORD=root`）后：
   - 打开 `http://localhost:9090/swagger-ui/index.html` → 下拉框能看到 5 个分组；
   - `http://localhost:9090/api/users/v3/api-docs` 返回 200 JSON；
   - 直连 `http://localhost:9092/swagger-ui/index.html`（及其余服务端口）也能看到各自的文档；
   - `http://localhost:9090/swagger-ui/index.html` 里点 "Authorize" 填 Bearer，再对 `/api/users/me/balance` 执行 "Try it out"，确认请求打到网关而非错误地址。
4. **Postman**：Import → 用 `/api/{svc}/v3/api-docs` 的 JSON 生成集合，核对参数与请求体是否齐全。
5. **关闭开关**：以 `SWAGGER_ENABLED=false` 启动任一个服务，确认 `/v3/api-docs` 返回 404（开关生效）。

## 风险与注意点

- **版本兼容**：Boot 3.5.6 + springdoc 2.9.1 需先做依赖解析验证；若 2.9.1 拉取失败/启动异常，退到 2.8.x 最新补丁版即可（同一 BOM 机制）。
- **路由顺序**：docs 路由若排在 `/api/xxx/**` 之后会被前者"吃掉"，`RewritePath` 不生效——务必前插。
- **网关聚合的 server 前缀**是这类方案最常见的坑，本方案用显式 `Server` 覆盖规避，属于**必须验证**项（见验证步骤 3 的最后一条）。
- **不要**为了让文档可访问而给 `/internal/**` 加网关路由（会破坏现有的"内部接口不出网关"边界）；内部接口继续直连服务端口 + `X-Internal-Token`。
- common-web 的 springdoc 依赖必须 `provided`，否则会把它传递给所有使用者。
- Nacos 里的 `gateway-service.yaml` 与 `docs/nacos/gateway-service.yaml` **两处都要改**，只改文件不改 Nacos 不会生效。
